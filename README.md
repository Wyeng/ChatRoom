# C++ 多人在线聊天室（ChatRoom）

## 一、项目简介

本项目是一个基于 **C++17、Windows Winsock2 和 TCP 协议**开发的命令行多人在线聊天室。

项目采用 Client/Server（客户端/服务端）架构，通过 Socket 实现网络通信，并使用 C++ 多线程技术支持多个客户端同时连接、发送和接收消息。

项目重点实践了 TCP 网络编程、消息边界处理、多线程同步、客户端会话管理和网络资源释放等 C++ 核心技术。

## 二、技术栈

| 技术 | 用途 |
|---|---|
| C++17 | 项目主要开发语言 |
| Winsock2 | Windows 平台 TCP Socket 网络通信 |
| TCP/IP | 实现客户端与服务端之间的可靠字节流传输 |
| std::thread | 多客户端并发处理 |
| std::mutex | 保护共享资源，协调线程访问 |
| std::atomic | 管理线程运行状态 |
| std::shared_ptr | 管理客户端会话对象的生命周期 |
| std::vector | 管理在线客户端及工作线程 |
| CMake | 项目构建管理 |
| Visual Studio | 开发与调试 |

## 三、项目功能

### 1. TCP 网络通信

- 服务端通过 `socket()` 创建 TCP Socket。
- 使用 `bind()` 绑定监听地址和端口。
- 使用 `listen()` 监听客户端连接。
- 使用 `accept()` 接受客户端连接。
- 客户端通过 `connect()` 连接服务端。
- 使用 `send()` 和 `recv()` 进行消息传输。

### 2. 多客户端并发

- 服务端为客户端连接创建独立工作线程。
- 支持多个客户端同时在线。
- 通过 `std::thread` 实现并发消息处理。
- 使用 `join()` 回收已结束的工作线程。

### 3. 用户名与群聊广播

- 客户端连接成功后输入用户名。
- 服务端记录客户端用户名。
- 客户端发送消息后，服务端将消息转发给其他在线客户端。
- 广播消息附带发送者用户名，便于识别消息来源。

### 4. TCP 消息边界处理

由于 TCP 是面向字节流的协议，不能保证一次 `send()` 对应一次 `recv()`。

项目采用换行符 `\n` 作为应用层消息分隔符：

- 客户端发送消息时添加换行符。
- 服务端通过接收缓冲区保存 TCP 数据。
- 使用 `find('\n')` 查找完整消息。
- 使用 `substr()` 提取消息。
- 使用 `erase()` 移除已经处理的数据。
- 保留尚未接收完整的消息内容。

该方案用于处理服务端接收过程中的 TCP 粘包和拆包问题。

### 5. 多线程同步与会话管理

- 使用 `std::mutex` 保护在线客户端列表。
- 使用 `std::atomic<bool>` 管理线程状态。
- 使用 `std::shared_ptr<ClientSession>` 管理客户端会话对象。
- 使用独立的 Socket 互斥锁协调广播发送和关闭操作。
- 使用互斥锁协调客户端控制台的输入与输出。

### 6. 资源清理与退出机制

- 客户端可以通过 `exit` 命令退出。
- 服务端可以通过 `exit` 命令请求停止。
- 使用 `shutdown()` 停止 Socket 通信。
- 使用 `closesocket()` 释放 Socket 句柄。
- 使用 `join()` 等待工作线程结束。
- 使用 `WSACleanup()` 清理 Winsock 资源。
- 使用 `select()` 超时机制定期检查服务端运行状态。

## 五、编译与运行

### 开发环境

- Windows 10 / Windows 11
- Visual Studio（支持 C++17）
- CMake
- Windows Winsock2

### 使用 CMake 编译

在项目根目录打开终端：

```bash
cmake -S . -B build
cmake --build build --config Debug
```

构建完成后，运行生成的服务端和客户端程序。

### 运行步骤

1. 启动 `ChatServer.exe`。
2. 启动一个或多个 `ChatClient.exe`。
3. 客户端连接成功后输入用户名。
4. 在客户端输入消息并按回车发送。
5. 其他在线客户端接收广播消息。
6. 输入 `exit` 退出客户端或停止服务端。

服务端默认监听 TCP 端口：`8888`。

## 六、核心技术难点

### 1. TCP 粘包与拆包

**问题：** TCP 不保留应用层消息边界，可能出现多条消息合并接收或单条消息分多次接收的情况。

**解决方案：** 使用换行符作为消息分隔符，并通过接收缓冲区缓存未处理数据，循环提取完整消息。

### 2. 多客户端并发管理

**问题：** 单线程阻塞式网络通信难以同时处理多个客户端。

**解决方案：** 为客户端创建独立工作线程，使用线程容器管理线程，并在工作线程结束后进行回收。

### 3. 共享资源同步

**问题：** 多个线程可能同时访问在线客户端列表，或同时操作客户端 Socket。

**解决方案：** 使用互斥锁保护在线列表，并通过客户端会话中的 Socket 互斥锁协调发送和关闭操作。

### 4. 客户端会话生命周期

**问题：** 客户端断开后，其他线程可能仍然需要访问其会话信息。

**解决方案：** 使用 `std::shared_ptr<ClientSession>` 管理会话对象，避免对象在仍被引用时提前销毁。

## 八、项目总结

通过本项目，实践并加深理解了以下知识：

1. TCP Socket 网络通信的基本流程。
2. TCP 字节流与应用层消息边界的关系。
3. C++ 多线程创建、同步和回收机制。
4. `mutex`、`atomic`、`shared_ptr` 等 C++ 工具的实际应用。
5. Socket 资源生命周期与客户端会话管理。
6. CMake 工程组织及 Visual Studio 调试。

本项目作为个人 C++ 网络编程实践项目，重点展示从基础 Socket 通信逐步实现多人在线聊天的开发过程。
